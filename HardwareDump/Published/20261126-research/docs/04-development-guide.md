# 04. Рекомендации разработчикам и план дальнейших работ

## Выбор SDK

Miyoo GCC 7.3.0 (`arm-miyoo-linux-uclibcgnueabi`) — предпочтительный эталон для динамической компоновки с GarlicOS 1.4.9, поскольку совпадает с доказанным происхождением SDL. Не объявлять имеющийся SDK полностью идентичным до проверки `-dumpmachine`, версии, sysroot, ABI и хешей библиотек. Buildroot GCC 9.4.0 — альтернативное окружение, совместимость зависит от конфигурации libc, kernel headers, ABI. Zig — альтернативное окружение, особенно для самостоятельных статических бинарников; проверять старое ядро, libc, ABI и библиотеки. Успешная сборка не равна успешному запуску.

### Три профиля

| | Эталон | Оптимизация Cortex-A9 | Эксперимент NEON |
|---|---|---|---|
| CPU | -mcpu=arm926ej-s | -mcpu=cortex-a9 | -mcpu=cortex-a9 |
| FPU | — | -mfpu=vfpv3 | -mfpu=neon |
| ABI | -mfloat-abi=soft | -mfloat-abi=softfp | -mfloat-abi=softfp |
| Opt | -O2 | -O2 | -O3 (сравнить с -O2) |

soft — программные вычисления, базовое соглашение вызова; softfp — позволяет VFP/NEON, сохраняет базовое соглашение передачи FP-аргументов; hard — использует иной VFP PCS, обычно несовместим с динамической компоновкой штатных soft-float библиотек. Softfp не ускоряет уже скомпилированную SDL/uClibc, только пересобранный код. NEON не гарантирует автовекторизацию; режимы fast-math меняют семантику, не включать глобально без тестов. Не гарантировать ускорение `-O3` или экономию RAM. Hard-float рассматривать только в полностью согласованном окружении или самостоятельном бинарнике после тестов ядра и ABI.

Шаблон `scripts/compiler-profiles.mk` — заготовка, а не полный SDK. Проверить каждый профиль на реальной приставке. Для оптимизаций лучше фиксировать одинаковую частоту, входные данные, компилятор/библиотеки, температуру, число прогонов; отдельно измерять FPS, время выполнения, размер файла и потребление RAM.

### Проверка SDK на Linux/WSL

```bash
export CROSS=/opt/miyoo/bin/arm-miyoo-linux-uclibcgnueabi-
"${CROSS}gcc" -v
"${CROSS}gcc" -dumpmachine
"${CROSS}gcc" -print-sysroot
"${CROSS}gcc" -print-file-name=libgcc_s.so.1
"${CROSS}g++" -print-file-name=libstdc++.so.6
"${CROSS}gcc" -Q --help=target
```

Сравнить sha256sum файлов SDK с `evidence/elf/manifest.csv`; несовпадение хеша не обязательно несовместимость (другая сборка/strip). Проверить `readelf -h -A -l -d -V` каждого готового ELF; нужные версии GLIBCXX/CXXABI и PT_INTERP должны соответствовать целевому окружению. Статическая компоновка `-static-libstdc++ -static-libgcc` может уменьшить зависимости от системных C++ символов, но увеличивает размер и не гарантирует совместимость с uClibc или Linux 3.10.37. Не копировать новую системную libc поверх старой.

## Портирование игр, включая Jazz Jackrabbit 2

- Для OpenJazz/SDL1 предпочтителен штатный fbcon и проверенный звук. Уже работающий порт — контрольный пример, не доказательство совместимости всех игр.
- Для Jazz Jackrabbit 2 сравнить ELF релиза Miyoo с профилем, выяснить библиотечные зависимости, renderer, SDL-версию, требуемые ресурсы и минимальный API. Совпадение ARM ISA недостаточно для запуска.
- Штатная SDL2 2.0.8 имеет только X11/dummy, software renderer. Если движок требует прямой framebuffer, изучить адаптированную SDL2 или подходящий платформенный backend; держать библиотеку локально в каталоге порта и проверять SONAME/ABI. Не заменять глобально /usr/lib/libSDL2*. Наличие GL/GLES не доказывает аппаратное ускорение.
- Оценить бюджет памяти (232 МиБ доступны ядру, без swap), избегать избыточных текстур и больших буферов. Проверить аппаратные кнопки, выход в меню, сохранения, частоту процессора, звук и восстановление состояния после выхода.
- Для диагностики использовать GDB 8.0, strace 4.20, ldd, `/proc/<pid>/maps`, `readelf` на хосте. Не включать ptrace на главном меню без необходимости: отладчик может приостановить процесс.
