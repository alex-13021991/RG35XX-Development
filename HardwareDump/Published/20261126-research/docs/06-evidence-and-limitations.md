# 06. Источники, ограничения, воспроизводимость

Дата исследования: 26.11.2026. Основные источники — пять оригинальных текстовых выгрузок терминала (private/) и семь ELF, собранных оператором с приставки (private/profile.zip). Журналы rootfs-inodes и rootfs-repair-and-comparison подтверждают checksum, debugfs, ссылки, промежуточный fsck, statfs, исходное ошибочное overhead и первое сравнение rsync. adb-initial/adb-chroot подтверждают mount, CPU, RAM, kernel, busybox, loop devices, успешный chroot и конечное df. garlicos-inventory содержит полные доступные списки библиотек и инструментов; часть вывода терминала перемешана из-за вставки команд. CSV построен только по распознанным строкам этих списков, не является полным рекурсивным каталогом всех файлов.

Поздние результаты e2fsck/rsync и CPUFreq, ldd, ALSA, Buildroot, framebuffer приведены оператором в сообщениях чата; ключевые строки отдельно перенесены в `evidence/logs/chat-results.txt`. Это выписки, не самостоятельные оригинальные файлы терминала. Начальные шаги до первой доступной выгрузки и промежуточные значения приведены по истории работы. Исходный исследовательский ZIP содержал протоколы. Владелец отдельно передал результат ремонта с сохранённой SHA-256 и копию, снятую по MTP с работающей приставки. Для каждого файла проверены SHA-256, ext4 и цели двух исправленных ссылок. ZIP для восстановления содержит образ до загрузки. [Образ и протоколы проверок](../../../../Firmware/GarlicOS-1.4.9-Repaired/) Сами 7 бинарников проверены повторно при упаковке; full readelf-отчёты — новые измерения.

Факты, которые нельзя считать установленными: физическая ёмкость RAM по чипу, стабильность максимальной частоты, активный refresh rate/RGB565 и фактическая тройная буферизация, работоспособность GPU API, коды кнопок, идентичность всех библиотек оригинальному SDK, производительность softfp/NEON, наличие аналогичного дефекта GarlicOS 1.4.8, первопричина повреждения inode и overhead, состояние остальных файловых систем после offline fsck. Нет автоматической гарантии совместимости портов и долговременной стабильности.

Уточнения к ранним выводам: `ldd` показывает и транзитивные зависимости, `readelf -d` — прямые DT_NEEDED. В SDL1 найден также DMA audio bootstrap; он не был перечислен в первоначальной краткой таблице. `-mfloat-abi=softfp` — рекомендованный эксперимент, не измеренный результат. Обнаружение symlink на модуль 4.14 не подтверждает ядро 4.14. Наличие Xorg или OpenGL не означает запущенный X11 или ускоренный GPU. 720 МГц — наблюдаемый лимит, а не аппаратный максимум.

## Приватность и права

В обеих опубликованных копиях журналов скрыты идентификаторы ADB и CPU, локальные имена оператора и компьютера. Технические строки сборки прошивки, пути SDK из ELF и UUID файловой системы установочного образа сохранены. Семь образцов ELF входят в исходный ZIP без изменения. Права на сторонние компоненты принадлежат их правообладателям. [Состав private/](../private/)

Для результатов за оба дня см. [сводный профиль](../../../../TechnicalProfile/README.md). В частности, формат RGB565 для fb0 определён через ioctl, события кнопок записаны на железе, а сборки с softfp прошли тесты 25 ноября.

## Проверка архива

Из корневой папки распакованного исследования на Linux: `sha256sum -c SHA256SUMS.txt`. Все вычисленные хеши относятся к конкретным файлам архива. В Windows: `Get-FileHash -Algorithm SHA256` для выбранного файла. Файл SHA256SUMS не включает собственный хеш. Повторное создание архива может изменить метаданные ZIP, не меняя содержимое вложений.
