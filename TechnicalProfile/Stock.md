# Проверка двух файлов в установочной GarlicOS

25 ноября 2026 года проверены оба установочных комплекта из предоставленного владельцем каталога `001_In/003`. В комплекте CopyPaste исследован `roms/CFW/rootfs.img`. В полном `garlic.img` тот же файл извлечён по цепочке кластеров из каталога `CFW` FAT32-раздела `ROMS`. Размер каждого rootfs — 209715200 байт, SHA-256 обоих — `b6cc0bb9c349c69a32c7ae28d7dea5394890f745da718fcd7dcb3551dcadfe9f`.

**Записи inode 817 и 818 повреждены уже в установочном образе для записи на microSD.** Ошибка воспроизводится при чтении файла образа на компьютере, без подключения приставки. Читаемые версии обеих библиотек извлечены из стока и [приложены с контрольными суммами](../SystemLibraries/Stock/README.md).

| Путь внутри rootfs | Установочная прошивка | Экземпляр владельца |
|---|---|---|
| `/usr/lib/libintl.so` | Inode 817. ext4 отвергает контрольную сумму записи | EIO при запросе метаданных, в журнале ядра ошибка inode 817 |
| `/usr/lib/libjson-c.so` | Inode 818. Та же ошибка контрольной суммы | EIO при запросе метаданных, в журнале ядра ошибка inode 818 |
| `/usr/lib/libintl.so.8.1.5` | ELF, 30164 байта, SHA-256 `8b2558b10b9de8432d8c9c1c61ee7badea1ce90b90ab65bd900af7b7a89dbb46` | Читается и байт в байт совпадает со стоком. Проверена загрузка по имени `libintl.so.8` и поиск функции `libintl_gettext` |
| `/usr/lib/libjson-c.so.3.0.1` | ELF, 46632 байта, SHA-256 `36d9cc8ea699e02e1b9a51100a36c699d0b8493c5a3fae2a861b58cda9f676d2` | Читается и байт в байт совпадает со стоком. Проверена загрузка по имени `libjson-c.so.3` и поиск функции `json_object_new_int` |

Имена соответствуют путям `/cfw/usr/lib/…` из внешней оболочки ADB. Обычный `debugfs stat` на ПК и `e2fsck -fn` независимо обнаружили ошибки inode. Чтение сырых записей через `debugfs -n` показывает, почему опасно доверять их содержимому. В 818 видна ссылка на постороннее имя `libgiomm-2.4.so.1.3.0`, а 817 описывает обычный файл. Проверка ext4 также сообщила о пересечении блоков и прервалась. Полный образ исправным считать нельзя.

Таким образом, дефект этих двух записей присутствует уже в предоставленных установочных комплектах. Ошибка на приставке объясняется состоянием исходного образа. Состояние физической карты по этому тесту не определяется. Проверка выполнялась в режиме чтения.
