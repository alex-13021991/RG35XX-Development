# Архитектура и границы достоверности

## Что найдено в исходных данных

В Windows входной backup содержит дерево сборки, SDK, исходники Jazz2 и отчёты прежних запусков QEMU (`qemu-intro.log`, `qemu-prince-01_castle1.log`, core dump). В полном индексе архива не найдено готовой VM: комплекта загрузочного ядра, дисковых образов и запуска qemu-system. Анализ выполнялся без запуска старых бинарников из backup. Полный индекс сохранён локально в `~/RG35XX/Work/qemu-audit/archive-files.txt`.

В `~/.cache/jazz2-rg35xx-release` Ubuntu 24.04 обнаружены sysroot, сборка игры и libopenmpt. Установлен qemu-user 8.2.2. В WSL зарегистрирована только Ubuntu-24.04; недоступный кеш Ubuntu 20.04 не исследовался. Для общей среды выбран sysroot из технического репозитория, а не изменённый игровой кеш.

## Устройство среды

1. Хост Ubuntu 24.04/WSL2 запускает Python CLI и PRoot от обычного пользователя.
2. PRoot предоставляет пути отдельного сеанса и передаёт ARM ELF в qemu-arm Cortex-A9.
3. ARM ELF загружает оригинальную uClibc и библиотеки sysroot. Динамический preload `devices.so` обрабатывает ограниченный список framebuffer/evdev ioctl.
4. fb0/fb1 — обычные mmap-файлы. Python преобразует RGB565 fb0 в RGB и показывает через Tk/WSLg. `FBIOPAN_DISPLAY` меняет отображаемый вертикальный offset.
5. Ввод из окна или CLI записывает ARM32 input_event в FIFO и обновляет файл состояния для EVIOCGKEY/EVIOCGABS. Поддерживается один потребитель evdev; это не multicast-очереди Linux input для нескольких процессов.
6. TF1/TF2 — разные каталоги внутри сеанса. Их содержимое сохраняется, но у них нет отдельных файловых систем, размеров и FAT-семантики.
7. Значение moto хранится в файле. GUI показывает последнее значение; короткие импульсы могут не попасть в очередное обновление GUI. Тест отдельно опрашивает его чаще.

Модель устройства — явная заглушка API. Строка имени framebuffer намеренно `RG35XX-QEMU`, чтобы не выдавать stub за драйвер `owlfb`. Неизвестные framebuffer/evdev ioctl возвращают ENOTTY. `EVIOCGRAB` завершается успешно без настоящей эксклюзивности. `FBIO_WAITFORVSYNC` — задержка около 16,7 мс, без реального дисплейного тайминга. Задержки, FIFO и ioctl не обеспечивают поведение реального ядра при гонках.

PRoot 5.1.0 переписывает LD_LIBRARY_PATH в QEMU-режиме. Поэтому файлы из `app/lib` подключаются поверх `/usr/lib` отдельными bind-путями на время сеанса. Исходный runtime при этом не меняется. ELF запускается напрямую: shell-скрипты комплекта не являются универсальным интерфейсом этой среды.

## Почему это не полная виртуальная приставка

В списке машин установленного qemu-system-arm 8.2.2 нет RG35XX/Actions/Owl/GS705A/ATM7039. Это проверено локально командой `qemu-system-arm -machine help`. Наличие модели CPU Cortex-A9 не означает наличие контроллеров RG35XX. Плата `vexpress-a9` — другая плата, а `virt` — синтетическая платформа. Подмена имени/параметров RAM не позволит корректно загрузить штатное ядро RG35XX.

QEMU linux-user переводит инструкции и системные вызовы в вызовы хоста. В этой среде нет гостевого Linux 3.10.37, гостевой физической памяти, четырёх моделируемых CPU, аппаратных прерываний, SD/MMC, ATC260x, USB Gadget, DMA, GPU/PowerVR, governor, термодатчика, энергопотребления и аппаратного вибромотора. Частоты 720–1488 МГц не калибруются.

Чтобы получить полную плату, потребуется отдельная разработка QEMU machine и моделей контроллеров с опорой на DTB, исходники/дизассемблирование ядра и документацию SoC. Затем — воспроизводимая загрузка штатного ядра, проверка MMIO/IRQ/DMA, SD-карт, дисплея, GPIO/кнопок и PMIC. Здесь такие модели не заявляются реализованными.

## Для чего пользоваться

Подходящие проверки: загрузка ARM ELF/зависимостей, ошибки ABI/инструкций, пути ресурсов/настроек, алгоритмы, смена кадров прямого fb0, evdev-коды, логика вибрации, файловые сохранения. Порты, использующие поддержанный путь framebuffer+evdev, можно запускать интерактивно.

На реальной приставке остаются обязательными: производительность, потребление памяти, latency ввода/звука, качество/громкость воспроизведения, аппаратные ioctl, энергопотребление, SD-карты, GPU и штатная цепочка запуска.

Не устанавливайте `ulimit -v 262144` как якобы точную RAM RG35XX: это ограничит адресное пространство хостового QEMU вместе с его служебными отображениями. `qemu-arm -R` тоже резервирует виртуальное адресное пространство, а не задаёт физическую RAM приставки.
