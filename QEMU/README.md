# QEMU: среда проверки приложений оригинальной Anbernic RG35XX

Готовая среда для запуска ARM ELF, проверки библиотек GarlicOS и тестирования портов с прямым framebuffer/evdev. Подготовлена в Ubuntu 24.04 под WSL2. Версия набора: 0.1.0, 27 ноября 2026 года.

**Это QEMU linux-user с программной моделью устройств, а не полная эмуляция платы RG35XX.** Не загружает оригинальное ядро или GarlicOS целиком. Успешный тест приложения здесь не заменяет тест на приставке.

## Быстрый запуск

Зависимости в Ubuntu 24.04:

```bash
sudo apt-get update
sudo apt-get install qemu-user proot python3 python3-tk binutils
```

Основной компилятор ожидается в `~/RG35XX/RG35XX-SDK/miyoo-gcc-7.3.0`. Для другого пути задайте `RG_TOOLCHAIN`.

Если каталог QEMU расположен в корне RG35XX-Development:

```bash
cd ~/RG35XX/RG35XX-Development/QEMU
./scripts/setup.sh
./rg35xx run
```

На подготовленной рабочей машине:

```bash
cd ~/RG35XX/QEMU
./rg35xx run
```

Первый запуск открывает демонстрацию 640×480 RGB565. Стрелки двигают белый квадрат, Z включает модель вибрации, Esc завершает ARM-приложение. Закрытие окна останавливает сеанс. После выхода приложения окно остаётся открытым для осмотра последнего кадра; закройте его перед повторным запуском.

Для архива с готовым runtime пересборка обычно не нужна: `./rg35xx run`. Сборки ARM независимы от пути установки. Сам QEMU устанавливается из Ubuntu; его исполняемый файл не дублируется в наборе.

## Что воспроизводится

| Часть | Реализация и границы |
|---|---|
| CPU | `qemu-arm -cpu cortex-a9`, ARMv7-A/VFP/NEON, ABI softfp/uClibc. Не моделируются частоты, CPUFreq, четыре физических ядра и их планирование |
| RAM | Реальные параметры: 256 МиБ, MemTotal 237624 КиБ. Лимита гостевой физической RAM в linux-user нет. `/proc` и RSS хоста не эквивалентны памяти приставки |
| Экран fb0 | 640×480, виртуально 640×1440, RGB565, stride 1280. Файл mmap, проверка и переключение страницы, окно через WSLg |
| fb1 | Геометрия 1280×720, виртуально 1280×1440, 32 bpp, stride 5120, R/G/B/A 0/8/16/24. Отображение второго экрана в окне не реализовано |
| TF1 | Постоянный отдельный каталог сеанса: `/mnt/mmc` |
| TF2 | Постоянный отдельный каталог сеанса: `/mnt/SDCARD` |
| Карты | Обычные каталоги, не SD/MMC-контроллеры, не FAT-разделы. Размер, скорость, ошибки карт и чувствительность FAT к регистру не воспроизводятся |
| Кнопки | ARM32 evdev, `event1` RG35XX Gamepad, `event0` Power. Коды из измеренного Controls.md, SYN_REPORT, имя, ID, capabilities, ABS range, текущие состояния, EVIOCGRAB-заглушка |
| Вибрация | Файловая модель `/sys/class/power_supply/battery/moto`, наблюдение значения в окне. Физической вибрации, PWM и точных временных характеристик нет |
| Библиотеки | Оригинальные из опубликованного sysroot: uClibc 1.0.28, SDL 1.2.15, SDL2 2.0.8 и другие. Частные библиотеки приложения доступны через overlay только во время запуска |
| Звук | SDL dummy, OpenAL null, ALSA null. Проверка логики/загрузки, без звука в колонках. Аппаратный ALSA mixer/HDMI/BT не воспроизводятся |
| Батарея | Явные фиктивные значения: 100 %, Full, 4 В. Не модель электроники или питания |

## Запуск приложения

Каталог приложения содержит ARM ELF, ресурсы и, при необходимости, `lib/`. Он подключается как `/app`, текущий каталог — `/app`.

```bash
./rg35xx run --session my-port --app /home/user/Work/my-port --exec my-program -- arg1 arg2
./rg35xx run --session ci --exec demo --headless --seconds 10 -- 60
./rg35xx run --session abi --exec probe --headless --seconds 20
```

Параметры среды передаются через `--env NAME=value`. Есть `--strace` для трассы системных вызовов QEMU. После `--` идут аргументы ARM-программы. `--seconds` ограничивает только headless-сеанс. Таймаут возвращает 124; обычный запуск возвращает код приложения.

GUI читает fb0 с частотой до 15 Гц: это частота просмотрщика, не игровая производительность. Для общего приложения SDL dummy сам по себе не даёт изображения: нужен прямой вывод fb0/evdev или отдельный совместимый backend. SDL1 fbcon, X11, GLES/EGL, PowerVR, VT/TTY, joystick `/dev/input/js*` и приватные Actions ioctl не реализованы. Статические ELF и прямые вызовы syscall обходят LD_PRELOAD и не получают эту модель ioctl.

## Управление

| Клавиатура | RG35XX |
|---|---|
| Стрелки | D-pad |
| Z / X | A / B |
| A / S | X / Y |
| Q / W | L1 / R1 |
| E / R | L2 / R2 |
| Enter / Backspace | Start / Select |
| Esc | Menu |
| + / − | Vol+ / Vol− |
| P | Power: только событие кнопки, без выключения WSL |

Альтернативная отправка кнопки из второго терминала:

```bash
./rg35xx key start --session my-port
./rg35xx key right --hold 1 --session my-port
./rg35xx screenshot /tmp/frame.ppm --session my-port
./rg35xx view --session my-port
```

## Файлы сеанса и безопасность

Каждый `--session NAME` имеет отдельный `state/NAME/root`. TF1/TF2 сохраняются между запусками. fb0/fb1 и состояния ввода очищаются перед новым запуском. Журнал — `state/NAME/console.log`, команда — `command.json`. Файл `lock` исключает два запуска в одном сеансе. Запуск не требует sudo.

PRoot переставляет пути, но **не является границей безопасности**. В режиме `-q` он открывает `/host-rootfs`; сеть остаётся сетью хоста. Запускайте только доверенные программы. Каталог приложения доступен для записи; используйте рабочую копию. Для потенциально недоверенных программ нужна отдельная VM/контейнер с самостоятельной политикой доступа. Набор не монтирует реальные диски, не создаёт настоящих устройств и не управляет Windows.

На TF1 создаются `CFW`, данные HOME и настройки. Для приложения, ожидающего `/cfw`, полную систему `/bin/sh`, procfs/sysfs или дополнительных устройств, нужно отдельно подготовить соответствующий пользовательский образ. Нельзя рассчитывать, что любой штатный launch.sh здесь запустится без адаптации. Пример Jazz2 запускает ELF напрямую и явно передаёт путь config.
